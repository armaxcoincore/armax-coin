## 2. Technical Summary of `v1.0.13` Hardening

### 2.1 Cryptography, Consensus & Storage Integrity (Tracks 1–2)
- **ML-DSA-65 Key/Seed Zeroization (`core/pqsig/pqsig.go`):** Added `ZeroizeBytes` to wipe sensitive seed and private-key buffers after key derivation and signing.
- **Network-Gated Canonical Hex & Coinbase/Genesis Rules (`Option 1A`, `core/transaction.go`, `core/blockchain.go`, `core/consensus.go`, `core/genesis.go`):** Enforced strict canonical lowercase hex (`isLowerHex` / `ValidateCanonicalHex`), strict `SigAlg`/extended-field coinbase checks, and strict Genesis `TimeLock`/`Preimage` checks on `ARMX-MAINNET-1`, while preserving `v1.0.12` uppercase-hex block/mempool relay and legacy coinbase/Genesis compatibility on `ARMX-TESTNET-1` (`Regtest`/`Soak`).
- **Pre-Snapshot Block & Per-Account Snapshot Verification (`core/storage.go`):** `LoadFromFile` now verifies pre-snapshot blocks (`validateBlockContext` + `tx.Verify()`) alongside per-account `Balance`/`Nonce` and immature coinbase state against snapshots, falling back to full genesis replay on any mismatch.
- **Reorg Mempool & `txindex` Safety (`core/consensus.go`, `core/blockchain.go`, `core/storage.go`):** Preserved sender-nonce ordering (`Nonce N` before `Nonce N+1`) during reorgs, enforced `MaxMempoolSize` after `CleanMempoolLocked()`, protected same-sender highest-nonce transactions during eviction, and preserved cross-height `txindex` integrity on reorg.
- **ASERT & Supply Guards (`core/asert.go`, `core/state.go`, `core/blockchain.go`):** Clamped extreme ASERT drift values and negative-height reward calculations, verified checkpoints in `IsChainValid`, and guarded `GetCirculatingSupply` against underclaim.
- **Serialized Fork Resolution (`core/consensus.go`, `core/blockchain.go` — PR `#33`, Track 7):** `ResolveFork` is now serialized by a dedicated reorganization lock, so two overlapping reorganizations can no longer interleave their undo-record rollbacks; the resulting state always matches a replay of the winning chain (regression test `TestResolveFork_OverlappingReorgsKeepStateConsistent`).
- **ML-DSA-65 Known-Answer & Protocol Vectors (`core/pqsig/`, `wallet/` — PR `#34`, Track 8):** Signature acceptance is consensus-critical, so it no longer relies only on the Go toolchain's own testing of `crypto/mldsa`. Vendored, SHA-256-pinned vectors now run through the consensus verification path in CI: NIST ACVP keyGen (`25` cases) and sigVer pure-with-context (`15`), Wycheproof verify (`210`: wrong lengths, non-canonical hints, infinity-norm violations, invalid contexts, zero keys; `acceptable` outcomes are rejected so every case has a fixed decision) and deterministic seed-based signing (`104`, byte exact). A golden test pins BIP-39 mnemonic → HKDF account seed → public key → `armx1...` address → mainnet/testnet sighash → deterministic signature → `VerifyWithError`, recomputing each step independently and rejecting cross-network replay. Two earlier tests that only logged or round-tripped values now assert pinned results. No consensus rule, wire format, or activation height changed.

### 2.2 P2P Networking, TLS & RPC Hardening (PR `#23`, `#26`, `#33` & Tracks 3, 7)
- **Sync Gate Peer Tip Claims (`node/p2p.go` — PR `#33`, Track 7):** Replaced the global, ever-increasing best-peer height with per-host `HEIGHT_RESPONSE` claims that expire after 5 minutes, count only when the peer reports more chainwork than the local chain, are ignored beyond a plausible height lead, and are dropped when the claiming peer delivers no block. `/getblocktemplate` and `/mine` therefore return to service once real peers are caught up, while initial block download from genesis is unaffected.
- **Inbound/Outbound Slot Isolation & Session Recovery (`node/p2p.go`, `node/fork_push.go`):** Enforced `MaxInboundPeersDefault = 38` and `MaxOutboundPeersDefault = 12` under `connLock`, heartbeat-agnostic non-seed LRU outbound eviction (`lastAppTraffic`), `8 MiB` `MaxIncomingPacketSize` with `32 MiB` aggregate large-frame lease budget (`2s` backpressure), `MaxInboundFingerprints = 2048` RAM FIFO cache, `MaxOrphanTxsPerPeer = 25` pre-verify reservations, strict `SeedHost` pin matching, and 3-minute periodic runtime map GC.
- **Clock-Skew Parity, Fail-Closed TLS & Disconnect Observability (`node/p2p.go`, `node/fork_push.go`, `node/p2p_crypto.go`):** Unified 3-tier `*core.FutureTimestampError` scoring across `ProcessIncomingBlock` and `handlePushedBlocks` (tip & reorg paths), aligned `1/8s` per-connection `GET_MEMPOOL` token refill, removed duplicate `SyncBestPeer` mempool broadcast, isolated non-timeout TOFU verification probes, filtered unreachable/stale peers from background gossip, enriched `[P2P][CONN]` debug logs with explicit disconnect `reason`, session `duration`, `msgs`, post-release `active` counts, and slot-rejection diagnostics, enforced TLS 1.3 `VerifyConnection` SPKI presence, and failed closed on corrupt `p2ptls.pem` when `RequireTLS` is enabled.

### 2.3 Wallet, CLI, GUI, Miner & Build Tooling (PR `#27`, `#28` & Tracks 4–5)
- **Network-Gated Relay Fee Policy (`Option 2A-i`, `core/network.go`, `core/blockchain.go`, `cli/armsend/main.go`):** Separated `MempoolBinaryFeeActivationHeight` (`0` on Mainnet, `-1` on Testnet) from `BlockBinarySizeActivationHeight` (`20000` on Testnet) via `FeeEffectiveTxSize`, preserving `11,000` Armoids JSON relay compatibility with `v1.0.12` Testnet nodes while activating `6,000` Armoids binary fee sizing on Mainnet from `#0`. `cli/armsend` queries `/stats` height before pre-sign balance checks.
- **Wallet, GUI & Miner Hardening (`wallet/`, `gui/`, `miner/`):** Enforced atomic `0600` writes with bounded `1 MiB` reads (`readBoundedFile`), zeroization of mnemonic/seed/key buffers, strict 24-word BIP-39 checksum enforcement, GUI localhost origin verification (`isStrictLocalOriginHost`) and constant-time session token checks, Stratum `MaxStratumLineBytes` (`256 KiB`) line framing, adaptive `5s`/`30s` C6 `prepareCandidateTimestamp` wait handling, and safe core affinity bitmask capping (`<= 62`).
- **Desktop GUI Peer Privacy & PoW/DAA Display Separation (`core/target.go`, `node/server.go`, `gui/privacy_sanitizer.go`, `gui/server_app.go`, `gui/web_ui.go`):** Separated the GUI Overview Network card into distinct `Difficulty Adjustment` (`Armax-ASERT-AW`) and `Algorithm` (`ArmaxHash v2`) rows backed by `pow_algo` / `pow_algo_name` on `/stats`, and added centralized backend-level IP/path sanitization (`RedactIPs` & `RedactLocalPaths`) masking public peer IPs as `Public Node` (`Endpoint hidden` / `P2P Peer`) in `/api/peers` while preserving DNS seed hostnames and CLI outputs.
- **Reproducible Build Flags, CI Concurrency & Dependency Pruning (`scripts/build.sh`, `scripts/build-all.ps1`, `.github/workflows/`, `go.mod`):** Aligned `CGO_ENABLED=0` and `-trimpath -ldflags="-s -w -buildid="` across all 5 binaries, enabled PR concurrency cancellation (`ci.yml`) and 1-day artifact retention (`release.yml`), and pruned 29 unused external module requirements from `go.mod` and `go.sum`.

## 4. Upgrading from `v1.0.12` to `v1.0.13`

`v1.0.13` shares identical Testnet consensus rules and BoltDB/keystore schemas with `v1.0.12`, enabling seamless rolling upgrades:

1. Ensure system clock is NTP-synchronized (`sudo timedatectl set-ntp true` on Linux, `w32tm /resync` on Windows).
2. Stop the running `v1.0.12` daemon gracefully and back up `blockchain.db`, `peers.json`, and your wallet keystore.
3. Download and verify `v1.0.13` release artifacts (`gpg --verify SHA256SUMS.asc SHA256SUMS` and `sha256sum --check --ignore-missing SHA256SUMS`).
4. Replace binaries, start `armcoind` / `armgui`, and confirm `armcoind -version` / `armgui -version` reports `v1.0.13`.
